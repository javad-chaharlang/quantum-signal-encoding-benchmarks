# FRQA Critical Assessment

## 1. Scope

This document provides a critical assessment of the FRQA baseline implemented in this repository. The assessment is limited to properties that have been reproduced or directly tested in the current implementation.

The evaluated implementation includes:

- signed amplitude representation using two's-complement encoding;
- explicit time and amplitude registers;
- preparation of the FRQA state for the primary-paper example;
- exact statevector probability inspection;
- shot-based reconstruction;
- logical circuit inspection;
- local sample-modification analysis;
- automated regression testing.

This assessment does not claim experimental quantum-hardware validation or cryptographic security.

## 2. Correctness of the implemented representation

The primary-paper example uses the signed signal

`[0, 1, 0, -1, 0, 2, 3, 1, -1, -2, -1, 0, 0]`.

The implementation reproduces the following encoding parameters:

- effective signal length: 13 samples;
- amplitude-register width: 3 qubits;
- time-register width: 4 qubits;
- total data qubits: 7;
- FRQA address space: 16 temporal positions;
- redundant temporal positions: 3.

The 3-bit two's-complement representations generated by the implementation are consistent with the signed amplitudes used in the example.

Exact-state analysis shows that every occupied FRQA basis state has probability approximately `1/16`, and the expected support of the encoded signal matches the generated state.

The reconstructed signal is identical to the original 13-sample input.

These results support the correctness of the implemented FRQA baseline for the validated example.

## 3. Reconstruction

Two reconstruction paths were examined.

First, exact statevector probabilities were decoded into `(time, signed_amplitude)` pairs.

Second, shot-based simulation was used to obtain measurement counts and reconstruct the original signal.

For the validated example, shot-based reconstruction returned

`[0, 1, 0, -1, 0, 2, 3, 1, -1, -2, -1, 0, 0]`

and the round trip was exact.

The result demonstrates that the implemented encoding and decoding conventions are mutually consistent.

It should not be interpreted as evidence that finite-shot reconstruction will remain exact for arbitrary signal sizes, shot budgets, transpilation settings, or noisy hardware.

## 4. Local modification behavior

A controlled local-modification experiment was performed by changing only sample index 5:

`2 -> 3`.

The exact FRQA probability distributions before and after modification were compared using a numerical tolerance of `1e-12`.

Only two statistically significant probability entries changed:

- the state corresponding to `(time=5, amplitude=2)` was removed;
- the state corresponding to `(time=5, amplitude=3)` was introduced.

The set of significantly affected temporal addresses was therefore

`[5]`.

No other temporal address changed above the selected numerical tolerance.

The resulting total variation distance was approximately

`0.0625 = 1/16`.

A separate shot-based reconstruction of the modified signal produced

`[0, 1, 0, -1, 0, 3, 3, 1, -1, -2, -1, 0, 0]`.

Relative to the original signal, the only reconstructed index that changed was index 5.

This experiment supports local addressability of the implemented FRQA representation: modifying one classical sample changes the encoded amplitude associated with the corresponding temporal address without changing the decoded values of the other samples.

This result does not by itself establish watermarking security, steganographic security, robustness, imperceptibility, or resistance to attacks.

## 5. Numerical comparison considerations

Direct floating-point equality is inappropriate when comparing independently simulated statevector probabilities.

In the local-modification experiment, unchanged probabilities differed only at approximately machine-precision scale. A raw comparison using `!=` incorrectly identified all temporal addresses as modified.

Using an absolute tolerance of `1e-12` correctly isolated the two physically meaningful probability changes at time index 5.

Future statevector and probability regression tests should therefore use explicit numerical tolerances rather than exact floating-point equality.

## 6. Logical circuit characteristics

For the validated 13-sample example, the generated logical circuit has:

- 7 qubits;
- depth: 40;
- size: 80 operations;
- 4 Hadamard gates;
- 16 multi-controlled-X operations;
- 60 X operations;
- 2 barriers.

The four Hadamard gates prepare the time-register superposition.

The controlled amplitude-writing stage associates signed amplitude bit patterns with temporal addresses.

Readable logical-circuit figures are provided as:

- `figures/audio/frqa/frqa_logical_circuit.png`
- `figures/audio/frqa/frqa_logical_circuit.pdf`

These values characterize the current logical construction and should not be interpreted as hardware-native resource counts. Decomposition, transpilation, coupling constraints, basis-gate selection, and hardware topology can substantially change the executable circuit cost.

## 7. Padding and redundant temporal positions

The signal contains 13 samples, while four time qubits provide 16 addresses.

Consequently, three addresses are redundant with respect to the effective signal.

The current implementation represents these unused temporal positions with zero amplitude.

This preserves a regular power-of-two address space but introduces representational overhead.

For larger non-power-of-two signals, this padding behavior should be considered when comparing resource efficiency across quantum audio representations.

## 8. Strengths of the FRQA baseline

The validated baseline has several useful properties.

First, positive and negative amplitudes are represented directly through signed two's-complement values.

Second, temporal addresses and amplitudes remain explicitly distinguishable in the decoded representation.

Third, the implementation reproduced the selected primary-paper example and supports exact and shot-based reconstruction.

Fourth, the local-modification experiment demonstrates sample-level temporal addressability in the tested representation.

Finally, the implementation is exposed through a reusable public API and is covered by automated regression tests.

## 9. Limitations

Several limitations remain important.

### 9.1 State preparation cost

Compact qubit count does not imply inexpensive state preparation.

The tested logical circuit already requires multi-controlled operations whose decomposition can substantially increase elementary gate count and depth.

Therefore, qubit efficiency and preparation efficiency must be reported separately.

### 9.2 Padding overhead

The time register requires a power-of-two address space.

Signals whose lengths are not powers of two introduce redundant temporal states.

### 9.3 Finite-shot behavior

The successful reconstruction experiment used a sufficiently large shot budget and an ideal simulator.

The current result does not establish the minimum shot count required for reliable reconstruction across larger signals.

### 9.4 Noise and physical hardware

The current FRQA validation is a logical/simulator baseline.

No claim is made here regarding robustness on a specific physical quantum processor.

### 9.5 Information-hiding security

Local addressability makes FRQA structurally relevant to applications in which selected samples or addresses may be manipulated.

However, locality alone does not demonstrate a secure watermarking or steganographic protocol.

Security-oriented conclusions would require a separately defined embedding algorithm, extraction procedure, threat model, attack set, robustness metrics, imperceptibility metrics, capacity analysis, and security evaluation.

Those properties are outside the claims of the present FRQA baseline assessment.

## 11. Assessment conclusion

The implemented FRQA baseline is sufficiently validated for use as a reproducible reference representation within this benchmark repository.

The strongest validated conclusions are:

1. the selected primary-paper signal is encoded with the expected register dimensions and signed amplitude representation;
2. exact-state support agrees with the expected FRQA representation;
3. the signal can be reconstructed exactly in the validated simulator experiment;
4. a one-sample modification remains localized to the corresponding temporal address under tolerance-aware exact-state comparison;
5. the modified signal is correctly recovered through shot-based reconstruction;
6. the implementation is protected by automated regression tests and repository-level QA.

The representation should nevertheless be treated as a baseline rather than evidence of practical quantum advantage or information-hiding security.

Any later watermarking, steganography, robustness, noise, or hardware study should define and validate those claims independently.
